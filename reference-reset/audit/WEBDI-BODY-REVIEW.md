# 웹디 — v7 헤더와 하단 본문 연결 검수

**판정: 하단 디자인 개선이 필요합니다. 다만 전체를 다시 만들 단계는 아닙니다.** 본문 정렬과 섹션 구분은 유지하고, 연결 결함 → 모바일 정보량 → 서체와 카드 스타일 순으로 정리하는 것이 맞습니다.

검수 대상은 원본 v12 본문에 v7 헤더만 연결한 별도 검수본 `page-review-v7.html`입니다. 원본 하단은 수정하지 않았습니다. 데스크톱 1280×720, 모바일 390×844에서 root가 이번 실행 중 캡처한 12장을 웹디가 파일로 직접 열어 확인했습니다. 웹디 서브 브라우저가 연결되지 않아 직접 클릭 관찰은 하지 않았으며, 소스와 root DOM 측정을 함께 사용했습니다.

## 우선 개선 5건

### 1. [P1] 헤더를 웹페이지용으로 연결해야 합니다
- **화면 근거:** [데스크톱 연결](00-desktop-connection.png), [모바일 연결](11-mobile-connection.png). 헤더 안쪽과 페이지 바깥쪽에 스크롤바가 각각 생깁니다. 단독 플레이어의 조작바까지 iframe에 들어가는데 부모 높이는 7:3 영상 영역만큼이어서 생긴 연결 문제입니다.
- **모바일 문제:** 데스크톱 7:3 화면을 약 350px 폭으로 축소하면서 장소·세부 날짜·버튼 문구가 읽기 어려울 정도로 작아집니다. 큰 12와 행사명만 남고 안내 기능이 약해집니다.
- **소스 근거:** 헤더의 ‘프로그램 보기 / 관람 안내’는 `.actions span`으로 만들어져 있어 본문 `#program` / `#guide`로 이동하는 실제 링크가 아닙니다. 이는 클릭 관찰이 아닌 소스 확인입니다.
- **수정 방향:** 임베드 모드에서는 내부 스크롤 없이 모션만 정확한 높이에 넣고, 조작부는 별도 접근 가능하게 구성합니다. 모바일은 모션 영역 아래에 날짜·장소·CTA를 정상 크기 HTML로 배치하거나 최종 헤더를 모바일 전용 배열로 전환합니다. CTA는 실제 앵커/버튼으로 부모 본문의 해당 섹션에 연결합니다.

### 2. [P1] 프로그램 시간축 라벨이 겹칩니다
- **화면 근거:** [데스크톱 작품 섹션 직전](03-desktop-works.png), [모바일 작품 섹션 직전](08-mobile-works.png). 시간표 아래 10–19시 표기가 왼쪽 좁은 구간에 겹쳐 읽히지 않습니다.
- **원인:** `.g-axis span{position:absolute}`가 첫 번째 빈 grid 자식까지 일반 흐름에서 빼서, `#gAxis`가 넓은 두 번째 트랙 대신 첫 번째 96px 트랙에 배치됩니다.
- **수정 방향:** `#gAxis{grid-column:2}`로 시간 라벨 컨테이너를 명시하거나, 첫 직계 빈 span만 일반 흐름으로 돌립니다. 데스크톱과 모바일 양쪽에서 각 시각이 막대와 맞는지 확인해야 합니다. 모바일 시간표 내부 가로 스크롤 자체는 현재 구조상 합리적입니다.

### 3. [P2] 미공개 카드를 너무 크게, 많이 펼칩니다
- **화면 근거:** [작품 데스크톱](03-desktop-works.png), [강의 데스크톱](04-desktop-lectures.png), [작품 모바일](08-mobile-works.png).
- **내용 근거:** 작품 12개가 모두 제목·창작자 ‘추후 공개’ 상태입니다. 강의 4개도 강사·제목·시간·정원이 미공개입니다.
- **규모:** 모바일 작품 섹션만 4,387px로 844px 화면 약 5.2개 분량입니다. 강의는 2,227px, 전체 문서는 18,418px입니다(root DOM 측정). 카드 사이 간격 문제보다 실제 정보가 없는 대형 카드의 반복이 문제입니다.
- **수정 방향:** 공개 전에는 GAME / ART / STORY를 대표하는 요약 3개와 ‘작품 공개 예정’ 안내로 압축하고, 강의도 오전 1회·오후 3회 일정 요약을 우선 보여줍니다. 정보가 들어오면 기존 그리드로 확장합니다. 확인되지 않은 콘텐츠를 채워 넣지 않습니다.

### 4. [P2] 본문 서체와 카드 표현을 헤더에 맞춰 정리할 필요가 있습니다
- **화면 근거:** [헤더→소개](01-desktop-intro.png), [기업 참여](05-desktop-partners.png), [모바일 연결](11-mobile-connection.png).
- **현재 상태:** 헤더는 굵은 Pretendard/Outfit과 직각 색면인데, 본문은 IBM Plex Sans KR 중심의 작고 옅은 설명문·둥근 흰 카드가 반복됩니다. 헤더를 내려온 뒤 다른 페이지처럼 보이는 원인이 됩니다. 본문 폰트가 깨졌다고 단정하는 것은 아닙니다.
- **수정 방향:** 본문 한글을 헤더와 같은 Pretendard 계열로 통일하고, 주요 설명은 모바일 15–16px 정도를 기준으로 읽기 강도를 확보합니다. 제목은 현재 크기를 크게 바꾸기보다 굵기와 자간을 통일합니다. 카드 반경과 흐릿한 장식은 줄이고 선·간격으로 구분하되, 본문 배경까지 전부 블랙으로 만들 필요는 없습니다. 선명한 헤더 색은 챕터 번호/선택 상태/핵심 정보에 한정해서 연결합니다.

### 5. [P2] 참여 안내에서 같은 대상 선택을 반복합니다
- **화면 근거:** [데스크톱 참여 안내](07-desktop-guide.png), [모바일 참여 안내](10-mobile-guide.png).
- **소스 근거:** ‘관람 / 무료강의 / 기업 참여’ 3개 경로 카드 다음에 동일한 3개 대상 탭이 다시 나옵니다. 경로 카드와 상세 안내 탭의 동작 목적은 다르지만 사용자는 같은 대상을 두 번 고르는 것으로 느낄 수 있습니다.
- **수정 방향:** 대상 선택을 한 번 하면 추천 동선과 참여 안내가 같은 블록에서 이어지도록 묶습니다. 모바일에서는 카드 3개 전체를 먼저 스크롤한 뒤 다시 탭을 고르는 길이를 줄이는 편이 좋습니다.

## 그대로 살릴 점
- 데스크톱 본문의 정렬축과 칼럼 간격은 일관적입니다. 카드의 무작위 밀림이나 제목 겹침은 확인되지 않았습니다.
- 큰 퍼플 챕터 번호와 제목 구조는 긴 페이지에서 현재 위치를 파악하기 좋습니다.
- [모바일 프로그램](09-mobile-program.png)의 날짜별 공개 시간 카드가 특히 명료합니다. 12.09 / 12.10과 일반 공개 시간을 구분하는 구조는 유지할 만합니다.
- 공간 사진, 프로그램, 작품, 참여 안내로 이어지는 큰 섹션 구분은 유지할 수 있습니다.

## 확인 범위와 한계
- 이번 검수는 화면·레이아웃·연결 구조 검수입니다. 신청 폼 제출, 외부 링크, 키보드/스크린리더 전수 테스트는 하지 않았습니다.
- 모바일 `scrollWidth=585` 측정값은 있으나 `overflow-x:hidden`과 화면 밖 요소의 영향 가능성이 있어, 실제 페이지 가로 흔들림 결함으로 판정하지 않았습니다.
- 작은 글자와 모바일 CTA는 읽기/조작 위험으로 지적했으며, 전체 접근성 기준 통과·실패를 선언하지 않습니다.
- 푸터 끝부분과 모든 탭 상태를 각각 캡처한 것은 아닙니다. 위 단계 표에 제시된 기본 화면을 중심으로 검수했습니다.
