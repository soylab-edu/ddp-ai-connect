### Student Kit에서 우선 참고할 것

README의 **YouTube motion showreel**은 하나의 붉은 점이 7개 장면을 지나 최종 로고의 일부가 되는 15초 구성으로 설명된다. 이 ‘하나의 형태가 계속 역할을 바꾸는 방식’을 01번의 전면 쇼릴 구조와 결합한다. 우리에게는 ‘사람 사이의 간격과 연결’을 반복 모티프로 제안한다. 카드 라이브러리의 숫자보다 장면 전체의 구도·리듬·형태 변환을 우선한다.

[MOTION_PHILOSOPHY](https://github.com/nateherkai/hyperframes-student-kit/blob/main/MOTION_PHILOSOPHY.md)는 타이포 크기 변화, 연결되는 전환, 최종 장면의 읽는 시간을 참고하기 좋다. 문서의 검정·크롬·발광 스타일은 해당 예제의 미술 방향이므로, 우리 01번 기준의 색·질감·화면 구성에 맞춰 별도로 판단한다.

### Skill Pack에서 우선 참고할 것

공개 목록의 **Four Steps | Events**, **The Curve**, **5 Skills Countdown**과 키네틱 타이포·연출 항목을 후보로 둔다. 행사 카피를 독립 장면으로 설계하고, 큰 글자의 등장·변형·퇴장과 다음 장면을 연결하는 데 참고한다. 이번 확인은 공개 설명과 문서 열람이며, 영상 전편을 직접 재생하여 평가한 것은 아니다.

현재 저장소는 Proprietary / All Rights Reserved로 표기되어 있으므로 여기서는 **연출 참고자료**로 분류한다. 특정 소스·에셋을 그대로 이식하는 경우의 조건은 별도이며, 레퍼런스로 검토하는 이번 작업을 막는 사유로 취급하지 않는다. [표기된 라이선스](https://github.com/imMamdouhaboammar/motion-graphics-skills/blob/main/LICENSE)

### 적용 방향 교정

사용자가 지적한 좌측 설명·우측 보라 도표 시안은 01번과 유사하지 않았다. 새 기준은 **헤더 전체를 하나의 모션 포스터로 사용하고, 사람 중심 카피를 압도적인 타이포와 형태 변화로 표현하는 것**이다. 날짜·장소·행사 성격은 별도의 얇은 정보 영역에서 읽히게 한다. SOYLAB은 사람이 함께할 자리를 만드는 브랜드로 나타난다.

## 기존 조사: Codex 제작 근거가 있는 보조 사례

아래 사례별 ‘우리 적용안’은 초기 탐색 기록이며, 이번 A/B 시안의 구현 지침이 아니다. 이번 제작은 사용자 지정 두 자료와 최신 전면 모션 포스터 기준을 따른다.

기존 조사 중에는 ① Codex Motion Studio, ② SignalSpace를 보조 후보로 남긴다. 두 저장소 모두 제작자의 Codex 사용 설명과 MIT 라이선스를 확인했다. 아래 적용안은 조사 단계의 디자인 제안이며, 해당 제작자의 추천이나 기존 결과물에 대한 묘사와 구분한다. 최신 우선순위는 위의 사용자 지정 자료와 최종 구성 설계 문서를 따른다.

실제 제작 여부는 제작자 README·직접 작성한 제작 후기·공식 커뮤니티에 수록된 제작자 설명을 기준으로 확인했다. 독립적인 제작 로그 감사를 했다는 의미는 아니다. CAN/DO는 공개 데모의 첫 화면을 실제 브라우저 스크린샷으로 확인했다. 다른 후보는 공개 페이지·README·시연 기록을 읽었으며 영상 전편을 직접 재생 검증하지 못했다. 로컬 HTML은 렌더링하지 않았고 원본을 수정하지 않았다.

## 1. Codex Motion Studio — 가장 직접적인 편집형 모션 레퍼런스

- **제작자·근거:** JakeB-5. README의 해당 샘플에 ‘remade with Codex using v0.4.0’이라고 명시되어 있다. 같은 저장소의 다른 샘플은 Claude 제작으로 따로 표기되어 있으므로, 저장소 전체를 Codex 작품이라고 묶지 않는다. [제작자 README](https://github.com/JakeB-5/motion-graphic-skill#codex-motion-studio--paper-cards--30-s)
- **데모·소스:** [영문 데모](https://jakeb-5.github.io/motion-graphic-skill/samples/codex-studio/?lang=en), [저장소](https://github.com/JakeB-5/motion-graphic-skill), [샘플 검토 기록](https://github.com/JakeB-5/motion-graphic-skill/blob/main/samples/codex-studio/review_log.md). README에 한국어 데모·소스 링크도 있다.
- **확인한 모션:** 30초·7장면. 크림색 종이, 큰 타이포, 보라·주황·민트 카드가 스토리보드·비트 시퀀서·HTML·휴대전화로 변하는 구성. 검토 기록은 초기 모바일 주소 글자 크기와 반복 전환 문제도 공개한다. 이는 우리 구현의 품질 보증이 아니다.
- **우리 적용안:** 종이 질감·주황·민트는 덜어내고 보라·라임·오프화이트로 제한한다. `間`의 획을 카드의 테두리·전시 패널·연결선으로 변환한다. 문구는 `AI를 사이에 두고 / 사람이 만나다` 한 문장으로 시작하고, 전시·상영·강의의 세 면이 間으로 다시 합쳐지게 한다.
- **라이선스:** [MIT](https://github.com/JakeB-5/motion-graphic-skill/blob/main/LICENSE) 확인. 코드를 가져오면 저작권·허가 고지를 보존한다. 외부 폰트는 별도로 확인한다.
- **한계:** 이번 조사에서 전편 재생·모바일 성능을 직접 확인하지 않았다. 원래 샘플의 16:9 플레이어와 시청 완료 뒤 열리는 링크 방식은 행사 헤더에 그대로 적용하지 않는다.

## 2. SignalSpace — ‘사람–AI–사람’ 연결을 표현하는 후보

- **제작자·근거:** Mahmoud Dahy. 직접 제출한 Devpost 설명과 README가 Codex/GPT-5.6을 사용해 Canvas 애니메이션·입자·원근 바닥·파동을 구현했다고 명시한다. [제작자 설명](https://devpost.com/software/signalspace), [소스 README](https://github.com/mahmouddahiie-pixel/signalspace)
- **데모·소스:** [공개 데모](https://signalspace-room.mdahy.chatgpt.site/), [GitHub](https://github.com/mahmouddahiie-pixel/signalspace). 핵심 경험 파일은 README 기준 `app/SignalGroundClient.tsx`.
- **확인한 모션:** 와이어프레임 참가자, 이동에서 발생하는 동심원과 입자, pulse/wave/glow, 원근 공간. 실시간 공동 접속 완성품이 아니라 브라우저 내 시뮬레이션 프로토타입이라고 제작자가 명시한다.
- **우리 적용안:** 인물·게임 조작·채팅 UI를 옮기지 않고, 세 개의 점·면을 `창작자 / 관람객 / 기업`으로 추상화한다. 라임 파동이 보라 공간을 가로질러 중앙의 間에 닿고, 마지막에 얇은 연결망으로 정리되게 한다. 제목 뒤를 비워 읽기 좋은 공간을 유지한다.
- **라이선스:** [MIT](https://github.com/mahmouddahiie-pixel/signalspace/blob/main/LICENSE) 확인. 필요한 그래픽 원리·로직만 검토할 수 있다.
- **한계:** 공개 데모 전편 동작·성능 미검증. 제작자도 reduced-motion·스크린리더 대안을 후속 과제로 적었다. 우리 헤더의 모바일·정지 상태·접근성은 별도로 설계해야 한다.

## 3. AI Tools Are Becoming Creative Teams — 세 주체를 연결하는 구성

- **제작자·근거:** Curtis / Kingy AI. 제작자 페이지가 Codex에서 HyperFrames로 10초 모션을 만든 시연, 첫 MP4 확인과 수정 과정을 설명한다. [제작 시연·공개 프리뷰](https://kingy.ai/videos/codex-motion-graphics-no-after-effects/), [원본 YouTube](https://www.youtube.com/watch?v=nIwmDN2_AEk)
- **데모·소스:** 제작자 페이지에 10초 브라우저 프리뷰·재현용 프로젝트·공개 워크플로 팩 링크가 있다. 페이지 자체가 현재 프리뷰는 9월 4일 재현본이며 촬영 당시 원본과 같지 않다고 구분한다.
- **확인한 모션:** 타이틀 → Script/Design/Video 세 카드 → 절제된 연결선과 카메라 전진 → 마지막 정지. 시연 중 겹침·작은 글자·불필요한 타이머를 수정했다는 기록이 있다.
- **우리 적용안:** 세 카드를 창작자·관람객·기업으로 바꾸는 발상은 잘 맞는다. 다만 SaaS 설명 화면처럼 보이지 않도록 둥근 UI 카드 대신 포스터 면·전시 패널·굵은 타이포로 바꾸고, 연결점이 間의 획으로 이어지도록 새로 설계한다.
- **라이선스·한계:** 원본 프로젝트·실행 로그는 제작자가 미보존이라고 명시. 재현용 팩을 공개했다는 사실만으로 임의 재배포 허가를 추정하지 않는다. 이번에는 연출 참고로 분류하며 다운로드하지 않았다. 광고 포함 시연이다.

## 4. CAN/DO — 큰 타이포와 3D 주인공의 결합

- **제작자·근거:** Fatih Kadir Akın (@fkadev). OpenAI 공식 Community에 Codex로 만들었다는 제작자 설명이 수록되고, 저장소가 제작 과정·Three.js 사용을 설명한다. [공식 커뮤니티 수록](https://developers.openai.com/community), [제작자 소스](https://github.com/f/can)
- **데모·소스:** [CAN/DO 공개 데모](https://blog.fka.dev/can/), [GitHub](https://github.com/f/can).
- **확인한 모션·디자인:** 실제 첫 화면에서 검정 공간, 매우 큰 흰 고딕과 이탤릭 글자, 스포트라이트를 받는 3D 캔 라인업을 확인했다. README는 라인업→주인공→폭발적 펼침→마지막 장면의 스크롤 전환, 가로 드래그와 키보드 조작을 설명한다.
- **우리 적용안:** 캔 대신 `間`을 얇은 입체 프레임이나 전시 패널로 만든다. 보라 프레임이 회전해 정면에 정렬되는 순간 라임 면이 사이를 통과한다. 실제 내용과 CTA는 회전하거나 화면 밖으로 나가지 않게 별도 고정한다. 01번의 평면 편집성이 우선이면 3D는 한 장면에만 쓴다.
- **라이선스:** 저장소 루트에서 코드 LICENSE를 확인하지 못했다. 캔 모델은 Jeremy / Poly Pizza, CC BY 3.0으로 별도 명시. 코드·캔·상표 그래픽을 그대로 재사용하는 후보가 아니라 움직임·구도 참고로 분류한다.
- **한계:** 전체 스크롤 시퀀스·모바일 FPS를 직접 검증하지 않았다. 제안한 間의 입체 표현은 새 디자인이다.

- **확인한 모션:** 제작 후기 기준, 디자인북의 글자·치수·페이지 구성을 유지하며 3D 휴대전화 내부 UI를 움직인다. 회전 중에는 내용을 숨기고 정착 후 카드·차트를 보여주는 식으로 속도와 읽는 시간을 조정했다.
- **우리 적용안:** 실제 휴대전화보다 ‘행사 포스터가 공간의 패널이 된다’는 변환이 적합하다. 먼저 정적 헤더의 글자 크기·그리드·행간을 확정하고 모든 컷에 같은 규칙을 유지한다. 헤더만 별도 영상처럼 다른 서체·장식으로 이탈하는 것을 방지하는 제작 방식 참고다.
- **라이선스·한계:** 앱 저장소는 Apache-2.0이지만, 게시된 모션 영화·디자인북·음악에 그 라이선스가 적용되는지는 확인하지 못했다. 영상 직접 재사용 대상에서 제외한다. 전편 직접 재생 미검증.

## 현재 제작 기준 — 두 개의 전면 헤더 시안

이전 작은 間 프레임·파동 연결망 제안은 제작 기준에서 제외했다. 현재 기준은 **01번처럼 헤더 전체를 쓰는 모션 포스터**이며, 원칙은 다음과 같다.

- 사람과 사람의 만남이 주제다. AI는 매개이고 SOYLAB은 함께할 자리를 만든다.
- 큰 글자·단색 면·형태 변환·컷 사이의 연결로 표현한다. 좌우 분할 랜딩과 박스 안 조직도를 만들지 않는다.
- 행사명·날짜·장소·행사 내용·참여 경로는 읽을 수 있는 고정 정보 영역으로 둔다.
- 창작 장르는 게임·예술·이야기 3개, 활동은 전시·상영·강의·교류, 참여자는 창작자·관람객·기업으로 구분한다.
- 약 12–16초 시퀀스 뒤에는 최종 화면을 유지한다. 시간은 실제 연출과 가독성 검수 결과에 따라 조정한다.

제작 A는 **대형 키네틱 타이포**로 사람이 만나는 의미를 표현하고, 제작 B는 **변형되는 형태와 열린 공간**을 중심으로 사람들의 모임을 표현한다. 두 안 모두 같은 행사 정보와 사람 중심 메시지를 유지한다. 세 번째 에이전트가 01번과 비교해 헤더·전체 페이지 연결·의미 전달을 검수한다.

## 실제 제작으로 넘어갈 때의 범위

1. 01번의 색을 복사하기보다 큰 글자, 넓은 여백, 일관된 그리드, 명확한 컷의 원리를 적용한다. 브랜드 색은 현재 보라 `#7A00EE`·라임 `#CCFF00`을 유지하는 방향을 먼저 검토한다.
2. 정적 첫 화면을 먼저 확정한다. 모션이 아직 시작하지 않았거나 꺼져 있어도 행사 정보와 행동 경로가 완성되어 있어야 한다.
3. 한 번의 짧은 시퀀스 후 정착하거나 절제된 루프로 전환한다. 재생·정지 조작과 reduced-motion 정적 상태를 함께 설계한다.
4. 로컬 파일을 구현·재생할 수 있는 승인된 경로가 확보된 뒤 첫 프레임, 컷 경계, 마지막 프레임, 모바일 글자 가독성, CTA 조작을 검증한다. 이번 조사는 구현·성능 검증을 대신하지 않는다.
